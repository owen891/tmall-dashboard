# Tmall Dashboard UI 收敛式落地方案

> 版本：v1.0  
> 日期：2026-10-01  
> 适用项目：`E:\www\tmall-dashboard`  
> 当前状态：实施中（基础组件与重点页面已落地，正在做剩余页面收敛与回归）

## 1. 目标

本次 UI 优化不做全量重构，不引入 React、Vue、TypeScript 或新的构建体系，继续采用现有的原生 JavaScript 组件方式。

核心目标只有三个：

1. **页面结构收敛**：23 个页面统一到少数几种页面模板。
2. **交互方式收敛**：筛选、表格、详情、数据状态统一。
3. **信息表达收敛**：首屏优先展示结论和行动，不再堆叠所有数据。

本次优先解决“页面复杂、入口太多、组件重复、信息层级不清”的问题，而不是继续增加视觉装饰。

---

## 2. 执行原则

### 2.1 不改变业务口径

第一阶段只调整：

- 页面结构；
- UI 组件；
- 样式；
- 交互层级；
- 数据状态展示。

暂不调整：

- API 字段含义；
- 指标计算逻辑；
- 数据库结构；
- 业务规则；
- 现有数据采集流程。

### 2.2 不做一次性全量改造

当前工作区已有较多未提交修改，实施时必须在现有 WIP 基础上小批次推进，不回滚、不覆盖已有业务改动。

每一批只完成一个明确目标，并通过页面检查和现有测试后再进入下一批。

### 2.3 不为每个页面单独发明一套 UI

页面只能使用统一的：

- 页面头部；
- 上下文筛选栏；
- 数据状态；
- 指标卡；
- 表格工具栏；
- 详情抽屉。

---

## 3. 页面模板收敛

所有页面统一归入以下五类。

| 页面类型 | 主要页面 | 统一结构 |
|---|---|---|
| 看板型 | 数据概览、经营中心、类目看板 | 结论 → 指标 → 异常 → 行动 |
| 列表型 | 商品、推广、市场排名、新品 | 筛选 → 表格 → 分页 → 详情 |
| 诊断型 | 商品详情、竞品、关键词、评价 | 结论 → 指标 → 证据 → 建议 |
| 配置型 | 数据中心、采集、设置 | 当前状态 → 待处理任务 → 配置 |
| 复盘型 | 周月复盘 | 范围 → 结论 → 问题 → 工作区 |

不再允许页面自由增加新的首屏结构。

---

## 4. 统一信息层级

### 4.1 页面顶部

每个页面只保留：

```text
页面标题 + 一句说明
时间 / 店铺 / 数据范围
一个主操作
```

示例：

```text
商品经营
查看商品销售、流量和库存表现

店铺：全部商品    时间：近30天    [导出数据]
```

### 4.2 页面主流程

所有页面都按以下顺序组织：

```text
先看结论
→ 再看指标
→ 再看异常或证据
→ 最后执行操作
```

### 4.3 操作层级

每个页面最多一个主操作，其余操作统一降级为次要操作或“更多”菜单。

主操作示例：

- 查看详情；
- 生成复盘；
- 开始采集；
- 保存设置；
- 导出数据。

## 5. 组件实现方案

### 5.1 技术决策

继续使用原生 JavaScript，组件入口为：

```text
E:\www\tmall-dashboard\frontend\ui_demo\assets\ui-components.js
```

不引入：

- React；
- Vue；
- TypeScript；
- Vite；
- 状态管理框架；
- 新的组件运行时。

### 5.2 核心组件范围

只建设以下 6 个公共组件：

| 组件 | 作用 |
|---|---|
| `PageHeader` | 页面标题、说明、主操作 |
| `ContextBar` | 时间、店铺、范围筛选 |
| `DataState` | 加载、无数据、失败状态 |
| `MetricCard` | 指标、趋势、辅助说明 |
| `TableToolbar` | 搜索、筛选、字段设置、导出 |
| `DetailDrawer` | 商品、计划、问题详情展示 |

现有组件可以复用和扩展，但不再继续增加大量相似组件。

### 5.3 数据状态收敛

页面 UI 只展示三类状态：

```text
加载中
暂无可用数据
加载失败
```

数据不足、字段缺失、部分数据可用等情况，统一作为辅助说明，不单独设计新的视觉状态。

示例：

```text
暂无可用数据
当前筛选条件下没有足够数据生成结论
[调整筛选] [去数据中心]
```

### 5.4 职责边界

```text
HTML：页面骨架和语义结构
CSS：设计 token、公共组件、页面布局
ui-components.js：通用组件生成和通用交互
xxx-live.js：接口请求、数据映射、页面业务事件
```

## 7. 页面落地顺序

### 第一批：基础组件

修改：

```text
E:\www\tmall-dashboard\frontend\ui_demo\assets\ui-components.js
E:\www\tmall-dashboard\frontend\ui_demo\assets\shell.css
E:\www\tmall-dashboard\frontend\ui_demo\assets\components.css
```

完成内容：

- 统一页面头部；
- 统一筛选栏；
- 统一数据状态；
- 统一指标卡；
- 统一表格工具栏；
- 统一详情抽屉。

验收重点：新组件可以被至少两个页面复用。

### 第二批：五个重点页面

按以下顺序迁移：

```text
数据概览
→ 周月复盘
→ 商品
→ 推广
→ 数据中心
```

#### 数据概览

目标结构：

```text
经营结论
核心指标
异常提醒
重点商品 / 重点问题
下一步动作
```

首屏优先回答：

- 当前经营表现如何；
- 最大增长点是什么；
- 最大风险是什么；
- 建议先处理什么。

#### 周月复盘

目标结构：

```text
复盘范围
经营结论
问题清单
复盘工作区
底部操作栏
```

工作区只保留必要 Tab：

```text
目标
差距归因
商品
推广
行动计划
```

#### 商品

使用标准列表结构：

```text
页面头部
上下文筛选
表格工具栏
商品表格
分页
```

商品详情统一使用右侧抽屉，不再继续增加页面级弹窗实现。

#### 推广

首屏只展示：

- 推广总览；
- 重点计划；
- 异常计划；
- 待处理事项。

详细计划、单元、关键词数据通过 Tab 或抽屉查看。

#### 数据中心

改造成任务导向页面：

```text
当前数据状态
最近更新时间
缺失数据
建议执行任务
```

普通用户不需要先面对复杂的字段表和配置项。

### 第三批：剩余页面

按页面类型批量迁移：

1. 列表型页面；
2. 诊断型页面；
3. 配置型页面；
4. 其他辅助页面。

不再按“一个页面重新设计一套”的方式推进。

### 第四批：清理重复实现

最后处理：

- 删除重复弹窗；
- 删除重复筛选器；
- 删除页面内重复状态渲染；
- 删除无用 CSS；
- 删除未使用的旧组件；
- 补充页面契约测试。

## 9. 验收标准

### 9.1 视觉验收

- 页面头部、筛选栏、按钮、卡片、表格风格统一；
- 同类页面不再存在明显不同的布局；
- 公共组件在多个页面复用；
- 移动端不出现横向溢出和操作挤压。

### 9.2 交互验收

- 每个页面只有一个主要操作；
- 表格页面工具栏位置统一；
- 详情统一使用抽屉；
- 空数据、失败、加载状态统一；
- 页面不需要通过多个弹窗才能完成主要任务。

### 9.3 信息验收

用户进入页面后应能快速回答：

1. 这个页面是做什么的；
2. 当前数据是什么情况；
3. 哪个问题最值得关注；
4. 下一步应该做什么。

### 9.4 工程验收

- 不破坏现有 API 契约；
- 不覆盖已有未提交业务修改；
- 页面脚本没有新增重复组件实现；
- 现有 UI 契约测试和页面校验通过；
- 新增公共组件至少被两个页面使用。

---

## 10. 明确不做

本次不做以下事项：

- 不引入 React/Vue；
- 不引入 TypeScript；
- 不引入复杂状态管理；
- 不重写所有接口；
- 不设计十几种用户可见的数据状态；
- 不为每个页面单独设计组件；
- 不在首页继续堆叠图表；
- 不同时改造全部 23 个页面；
- 不为了视觉效果增加无必要动画；
- 不增加复杂的多级筛选体系。

---

## 11. 最终目标

完成后，项目 UI 应形成以下稳定结构：

```text
少数页面模板
+ 少数公共组件
+ 统一筛选和表格
+ 统一详情抽屉
+ 统一三类数据状态
+ 统一首屏信息层级
```

核心判断标准不是页面看起来更复杂，而是：

> 页面更容易理解，操作路径更短，组件重复更少，后续新增页面更容易复用。
