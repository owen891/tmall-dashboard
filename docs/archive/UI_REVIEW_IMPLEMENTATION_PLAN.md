# UI 评审落地实施方案

**文档版本**：v1.0  
**编制日期**：2026-09-19  
**适用项目**：tmall-dashboard  
**文档状态**：待实施  
**评审基线**：当前工作树及本地 UI Demo；包含未提交变更  

---

## 1. 文档目的

本方案将当前 UI 评审结果转化为可执行、可验收的改造任务。范围覆盖：

- 商品运营、数据中心、经营概览、推广分析、素材点击率看板；
- 公共导航、日期上下文、URL 状态和响应式布局；
- UI 组件契约、浏览器门禁和视觉静态检查。

本方案优先处理会影响运营判断、数据解释和关键操作反馈的问题，不以继续增加页面数量为目标。

### 1.1 核心目标

1. 所有数据状态可被正确解释：区分无数据、样本不足、字段缺失、真实为零和计算失败。
2. 核心操作有完整反馈：映射、校验、导入、撤销、筛选、重置和视图切换必须可感知、可恢复。
3. 页面状态可复现：跨页共享状态和页面私有状态有明确 URL 契约。
4. 桌面、平板和移动端保持核心任务可用，不以隐藏功能代替响应式设计。
5. 自动门禁反映当前实现，新增页面不能绕过既有 smoke、交互和视觉检查。

### 1.2 非目标

本轮不包含：

- Flask API、数据库表结构或业务指标口径的整体重构；
- 新增分析页面或新增经营指标；
- Electron 架构替换；
- 与本次 UI 评审无关的采集、发布、安全和部署问题；
- 已经完成且没有新证据支持的旧版 UI 问题返工。

## 2. 当前结论

### 2.1 总体判断

项目已经完成公共 Shell、设计 token、多个页面动态数据接入和部分响应式改造，当前主要问题从“缺少页面能力”转为“状态语义、操作反馈和测试契约不完整”。

当前没有证据表明存在 UI 层面完全阻断所有核心流程的 P0 问题，但以下 P1 问题会影响用户判断或造成操作结果与界面不一致，应优先处理。

### 2.2 优先级定义

| 等级 | 定义 | 处理要求 |
| --- | --- | --- |
| P0 | 阻断核心任务或导致关键数据被错误使用 | 发布前必须修复 |
| P1 | 影响判断准确性、状态反馈或核心操作效率 | 第一阶段处理 |
| P2 | 明显影响可读性、响应式体验或可访问性 | 第二阶段处理 |
| P3 | 设计系统、测试覆盖和维护性问题 | 第三阶段收口 |

### 2.3 已收口、无需重复处理

以下问题在当前实现中已有明显改进，不再作为本方案的重复改造目标：

- 概览页已增加数据上下文、经营判断、目标进度、提醒和日度矩阵；
- 商品页已接入服务端分页、搜索、筛选、排序、收藏、字段模板和移动摘要；
- 推广页已拆分总览、计划、商品三个视图，并有渠道口径说明；
- 数据中心已具备多文件预览、字段映射、质量校验、导入历史和撤销入口；
- 素材看板已从推广商品页中独立出来，并明确“全历史、无日期筛选”的产品语义；
- 公共 Shell 已具备移动导航、日期控件和跨页面基础 URL 状态恢复；
- 多数核心页面已经使用 tokens、shell 和 components 资源。

这些能力仍需纳入回归测试，但不应再按“完全缺失”进行设计。

## 3. 问题与落地任务

## 3.1 P1：商品单日口径未真正生效

### 现状证据

- `frontend/ui_demo/assets/products-live.js:289-294` 的 `shouldUseDailyData()` 会在起止日期相同的时候返回 `true`。
- `frontend/ui_demo/assets/products-live.js:359-363` 已计算 `dim`，但 `:364` 构造请求参数时仍写死 `dim: 'monthly'`。
- 页面会按单日范围展示日度提示，但实际请求仍可能使用月度维度。

### 影响

用户选择单日数据后，页面提示、请求参数和结果口径可能不一致，直接影响商品排名、销售额和 ROI 判断。这属于数据解释问题，不是单纯排版问题。

### 实施要求

1. 请求参数使用已计算的 `dim`，避免在参数对象中重复写死维度。
2. 对单日、跨日和无日期三种场景定义明确请求规则。
3. 在请求失败或后端不支持该维度时显示“当前口径不可用”，不得静默回退到另一维度。
4. 将 `dim` 纳入请求调试信息或可访问说明，便于浏览器门禁验证。

### 涉及文件

- `frontend/ui_demo/assets/products-live.js`
- 商品 API 对应的维度参数处理代码
- `tests/test_products_prd.py`
- `scripts/browser_prd_gates.cjs`

### 验收标准

- 单日范围请求包含 `dim=daily`、`start` 和 `end`。
- 跨日范围请求遵循既定月度口径，并在界面上显示对应说明。
- 浏览器测试能拦截请求并断言实际维度，而不仅断言页面提示文本。
- 页面刷新、前进和后退后，日期范围与维度保持一致。

## 3.2 P1：商品筛选重置不完整

### 现状证据

- `frontend/ui_demo/assets/products-live.js:338-355` 的 `filters()` 已读取 `lifecycle_stage`、`seasonality` 和 `has_pending_action`。
- `frontend/ui_demo/assets/products-live.js:1101-1117` 的 `resetFilters()` 未清空这三个高级筛选。
- 这些筛选同时参与 URL 和请求参数，重置后可能仍保留旧条件。

### 影响

用户点击“重置”后看到的列表仍可能被隐藏条件过滤，容易误以为系统数据异常，也破坏“重置后可复现”的基本操作预期。

### 实施要求

1. 将所有 `filterKeys` 作为重置的唯一来源，避免新增筛选后遗漏。
2. 重置表单值、内存状态和 URL 参数，三者必须一次完成。
3. 重置后恢复默认排序、页码和收藏模式，并重新加载数据。
4. 增加“已应用筛选”摘要，便于确认重置是否生效。

### 验收标准

- 逐一设置基础筛选和高级筛选后点击重置，所有控件回到默认值。
- URL 不再保留旧的生命周期、季节属性和待办动作参数。
- 请求不再携带旧筛选，列表和 KPI 恢复到默认结果。
- 浏览器回退不会把已重置筛选错误恢复到页面内部状态。

## 3.3 P1：数据中心导入流程反馈不完整

### 现状证据

- `frontend/ui_demo/pages/data-center.html:17-18` 的四步 stepper 只有第一步静态标记为当前步骤。
- `frontend/ui_demo/assets/data-center-live.js:116-180` 负责预览和确认导入，但未同步更新 stepper 的 `is-current` / `is-done` 状态。
- `frontend/ui_demo/assets/data-center-live.js:98-107` 的字段映射 change 事件更新了数据对象和状态文案，但没有更新对应表格单元格 `matchCell.textContent`。
- `frontend/ui_demo/assets/data-center-live.js:84-90` 先设置字段警告，随后无条件将详情覆盖为“未发现异常行”。
- `frontend/ui_demo/assets/data-center-live.js:198-205` 使用原生 `window.confirm`，与设计系统规定的 `TmallUI.confirm` 不一致。

### 影响

用户无法确认当前导入处于哪一步；手动映射后表格仍显示旧状态；字段级质量问题可能被错误显示为无异常；撤销是高风险操作，却没有使用统一确认组件。

### 实施要求

1. 为上传、预览校验、字段映射、质量确认和入库完成建立明确状态机；界面仍保持现有四步流程，字段映射与质量校验作为中间状态，不额外增加用户步骤。
2. 每次状态变更同步 stepper 的当前、已完成和错误状态。
3. 字段映射变更时同时更新数据对象、匹配状态单元格和必填映射摘要。
4. 质量详情按优先级合并：行级错误、字段警告、重复键和其他质量结论不可互相覆盖。
5. 撤销批次统一使用 `TmallUI.confirm({ tone: 'danger' })`，确认内容必须包含影响范围。
6. 保留失败文件的可重试入口，并明确成功文件和失败文件数量。

### 验收标准

- 完成每一步后，现有四步 stepper 显示当前步骤和已完成步骤；字段映射与质量校验的中间状态可见，失败时显示错误步骤并保留恢复入口。
- 修改字段映射后，表格立即显示“手动匹配”或“未匹配”，无需重新预览。
- 存在字段警告但没有行级错误时，详情区域仍显示字段警告，不显示“未发现异常行”。
- 撤销操作使用统一确认弹窗，ESC、取消和确认行为符合 Modal 契约。
- 多文件导入部分失败时，可只重试失败文件，且历史记录反映最终状态。

## 3.4 P1：概览数据质量徽标和缺失值语义不准确

### 现状证据

- `frontend/ui_demo/pages/overview.html:29-32` 的质量徽标默认静态显示“质量通过”。
- `frontend/ui_demo/assets/overview-live.js:253-277` 的 `renderContext()` 主要更新上下文文本，没有根据 availability、partial、no-data 或 missing-fields 改写质量徽标。
- `frontend/ui_demo/assets/overview-live.js:319-339` 的目标渲染主要依据 `actual.gsv != null` 判断整体可用性；缺失子字段仍可能进入金额格式化路径，需按字段逐项校验，不能把缺失字段当作真实零值。

### 影响

数据缺失或部分可用时，用户可能把页面当作完整数据使用；缺失值被显示为零会直接改变经营判断。

### 实施要求

1. 统一 availability 状态到质量徽标、模块级 DataState 和辅助说明。
2. 对缺失、不可计算、真实为零分别使用 `--`、`不可计算` 和 `0` 等明确展示。
3. 目标进度按字段逐项判断，不能只根据一个总指标推断整体可用。
4. 质量徽标必须能链接到数据来源、更新时间和缺失字段说明。

### 验收标准

- `available`、`partial`、`no-data`、`missing-fields`、`source-unavailable` 等状态显示不同语义标签。
- 缺失目标字段不显示为零；真实零值仍显示为零。
- API 返回部分数据时，页面首屏不会出现“质量通过”误导性文案。
- 单元测试覆盖每种 availability 状态，浏览器测试至少覆盖 partial 和 no-data。

## 3.5 P2：推广计划交互和图表生命周期

### 现状证据

- `frontend/ui_demo/assets/promotion-views-live.js:306-345` 使用整行 `tr` click 展开计划详情，没有明确的键盘可操作控件和展开语义。
- `frontend/ui_demo/assets/promotion-views-live.js:36-59` 定义了 `disposeCharts()`，但在视图或日期刷新路径中没有稳定调用。
- 切换总览或重复刷新可能把同一 ECharts 实例继续加入 `state.charts`，造成引用累积。

### 影响

键盘用户无法发现或操作计划展开；长期切换视图可能增加无效图表引用，形成性能和清理风险。

### 实施要求

1. 将计划展开改为行内按钮或 `button`，提供 `aria-expanded`、`aria-controls` 和明确焦点样式。
2. 统一处理 Enter、Space、点击和关闭详情的行为。
3. 在重新渲染、切换视图和页面销毁前调用图表 dispose，并清空实例集合。
4. 对重复刷新进行引用数量和 DOM 节点数量检查。

### 验收标准

- 不使用鼠标时可以完成计划展开、收起和下钻。
- 屏幕阅读器可获知行是否展开及展开内容关联关系。
- 连续切换总览/计划至少 10 次后，图表实例数量不增长，页面无 console error。
- 视图切换后旧图表不会继续响应 resize 或数据更新。

## 3.6 P2：素材看板窄屏布局和状态可复现性

### 现状证据

- `frontend/ui_demo/assets/creative-board.css:40-43` 在 `900px` 以下将创意行首列改为 `48px`。
- `frontend/ui_demo/assets/creative-board.css:26-29` 的缩略图仍固定为 `64px × 64px`，存在首列溢出和内容挤压风险。
- `frontend/ui_demo/assets/creative-board-live.js:23-29` 只将 `category` 纳入 URL，搜索词为本地状态。
- `frontend/ui_demo/assets/creative-board-live.js:91-109` 的筛选动作不会同步更新可分享的搜索状态，汇总数字也没有明确说明是全量还是当前筛选结果。

### 实施要求

1. 窄屏使用与图片实际尺寸一致的网格列，或在窄屏将缩略图缩小到列宽内。
2. 移动端搜索框独占一行，品类筛选使用横向滚动或可访问的选择控件。
3. 明确汇总指标的统计范围：全量、当前品类或当前搜索结果。
4. 若产品要求可分享搜索结果，将 `search` 纳入素材页私有 URL 状态；否则在文档和界面中明确搜索为临时本地筛选。
5. 为素材列表增加排序或快捷视图，优先支持 ROI、花费、点击率和样本量。

### 验收标准

- `390px`、`480px`、`768px` 宽度下缩略图不溢出，创意名称不被图片遮挡。
- 搜索框 placeholder 和输入内容可见，筛选控件不挤压主要操作。
- 页面刷新或复制链接后，已纳入 URL 的筛选状态可恢复；未纳入的状态有明确产品说明。
- 对低样本、零花费和零点击素材显示可解释状态，不把 `0/0` 误认为有效率值。

## 3.7 P2：移动端商品页功能降级需要显式定义

### 现状证据

- `frontend/ui_demo/assets/products-live.js:660-703` 在窄屏主要渲染移动摘要。
- `frontend/ui_demo/assets/components.css:923-936` 隐藏桌面商品表。
- 字段模板、列设置、批量操作和大部分商品字段在移动端不直接可见。

### 实施要求

1. 明确移动端是“查看优先”还是“完整运营操作”模式。
2. 如果是查看优先，移动摘要必须提供进入详情、筛选状态和批量操作不可用原因。
3. 如果需要完整运营操作，补充移动端详情抽屉或操作面板，而不是直接隐藏能力。
4. 在页面帮助文案中说明移动端可用范围，避免用户把隐藏理解为数据缺失。

### 验收标准

- 移动端用户能看到当前筛选、排序和分页状态。
- 商品详情、收藏和必要的单项操作可完成。
- 被隐藏的批量能力有明确替代入口或说明。
- 不以 CSS 隐藏造成无法通过键盘或辅助技术访问的孤儿控件。

## 3.8 P3：导航、日期和页面私有 URL 契约需要统一

### 现状证据

- `frontend/ui_demo/assets/navigation.js:2-5` 的白名单只包含日期、商品、层级、生命周期、推广渠道和动作等参数。
- 当前页面另有页面私有状态，例如素材 `category`、推广 `tab/channel/campaign_id/unit_id`、商品 `page/page_size/starred`。
- `frontend/ui_demo/assets/shell.js` 在初始化时可能以最新导入日期更新日期锚点，而部分测试契约要求以浏览器当前日期为锚点；这是当前未冻结的产品契约冲突，不能在未决策前直接判定某一方为唯一正确实现。

### 实施要求

1. 将 URL 参数分为跨页面共享状态、页面私有状态和不支持状态三类。
2. 明确 `start/end/preset/compare` 的锚点规则：系统今天或最新数据日只能选择一种，并同步实现、测试和产品文案。
3. 统一决定哪些私有状态可分享、可恢复和可跨导航保留。
4. 导航测试遍历正式路由和页面，而不是只维护一份容易过时的页面数组。
5. 当前页面使用 `aria-current="page"` 与视觉 active 状态保持一致。

### 验收标准

- 每个正式页面都有 URL 状态契约测试。
- 日期快捷范围在实现、静态测试、浏览器测试和文案中使用同一个锚点。
- 页面私有参数不会被公共导航无意丢失；明确不保留的参数不会造成错误恢复。
- 当前导航项在 DOM、视觉和辅助技术语义上保持一致。

## 3.9 P3：浏览器门禁和视觉扫描与当前实现同步

### 现状证据

- `scripts/smoke_core_pages.cjs:5-14` 未包含新增 `creative-board` 页面。
- `scripts/smoke_core_pages.cjs:173` 仍要求 `navCount !== 7`，而当前 Shell 已注册约 15 个导航项。
- `.github/workflows/quality-gate.yml:72-74` 使用 `TMALL_CAPABILITY_ONLY=1 node scripts/browser_prd_gates.cjs`，完整浏览器门禁因此没有在 CI 默认执行。
- `scripts/validate_visual_system.cjs` 主要读取 tokens、shell 和 components，未覆盖页面专属 CSS。

### 实施要求

1. 将 `creative-board` 纳入其所属级别的 smoke、交互和响应式测试清单。
2. 导航数量断言改为导航注册表或页面契约断言，不使用过时的固定数字。
3. 将 capability-only 检查与完整 browser gate 拆成两个明确命令，CI 默认执行完整门禁。
4. 视觉扫描覆盖所有页面专属 CSS，或建立清晰的豁免清单和对应测试。
5. 对页面列表、导航列表和路由白名单建立单一来源或生成式校验。

### 验收标准

- CI 中完整 browser gate 实际执行日期、模板、移动端、历史回退和可用性状态检查。
- smoke 不因导航项从 7 增加到 15 而产生无意义失败，同时能发现导航缺失、重复和错误目标。
- `creative-board` 至少覆盖加载、品类切换、搜索、窄屏布局和错误状态。
- 页面专属 CSS 中新增 raw color、硬编码阴影、圆角和字号能够被检查或明确豁免。

## 6. 风险、回滚和依赖

### 6.1 依赖

- 商品维度修复依赖后端 `/api/products` 对 `daily` 参数的既有支持；若后端不支持，必须先补充能力状态，不得静默降级。
- 数据中心 stepper 修复依赖现有预览队列和导入结果状态，建议先定义状态枚举再调整 DOM。
- URL 契约调整必须与 `navigation.js`、`shell.js` 及各页面 live 脚本同时发布。
- 完整 browser gate 恢复前，应确认测试服务器、Playwright 浏览器和测试数据可稳定启动。

### 6.2 回滚原则

- 每一阶段独立提交，不跨阶段删除旧兼容行为。
- UI 状态改造优先保留原 API 请求和数据结构，出现问题时可回退到旧渲染分支。
- URL 白名单扩展应向后兼容旧链接，不删除已有共享参数。
- CI 门禁调整先以报告模式运行，再切换为阻断模式；不能通过跳过测试解决失败。

### 6.3 风险清单

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 日度接口字段与月度接口不同 | 商品页渲染失败 | 增加响应 schema 校验和 capability 状态 |
| 导入流程状态过多 | stepper 与真实状态不同步 | 使用单一状态机和状态转换表 |
| URL 参数增加导致历史链接变化 | 旧链接不可恢复 | 保持旧参数兼容并增加迁移解析 |
| 完整 browser gate 暴露历史失败 | CI 时间和修复量增加 | 先分类现有失败，再分阶段恢复阻断 |
| 页面专属 CSS 规则误报 | 新页面无法合并 | 提供带理由的显式豁免，不降低全局规则 |
