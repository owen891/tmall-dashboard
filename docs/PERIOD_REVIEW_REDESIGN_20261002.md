## 0. 结论先行

**上一轮（9/29 P0–P3）已经把 "功能" 补齐了**：三段式段落、问题单品聚合、复盘导出、

四大叙事 tab、经营驾驶舱、目标完成率卡全部在线，测试 849 项全绿。用户仍觉得 "不好用"，

说明**问题不在功能缺失，而在信息架构与任务流**：

> 页面把 "看数据" 和 "写结论" 两种任务平铺在四个 tab 里；写作区被推到首屏 2.5 屏
> 支撑信息之后；每段证据全部折叠；写结论必须来回切 tab 对照数据。

**本次重构方向：从 "四 tab 功能工作台" 改为 "写作优先的单页流 + 数据侧抽屉"。**

让 "完成一期复盘"（看结果 → 写六段 → 存 / 导出）成为一条**不需要切 tab** 的纵向主流程。

不动数据口径、不砍任何现有能力、不重建后端。



* 分两期落地：**P1 纯前端布局重排（0.5–1 天）** → **P2 数据抽屉 + 表格压缩（1–2 天）**。

* 首屏验收硬指标：1280×800 内看到 "结果 HUD + 六段写作区的前两段"，且写任意一段时

  无需切换即可看到该段核心证据。

## 1. 现状诊断（代码级 + 真实页面）

### 1.1 页面现状（2026-10-02 实测）

页面总高约 5,560px（≈ 7–8 屏），自上而下依次是：



| 区块           | 实际内容                               | 高度占比          |
| ------------ | ---------------------------------- | ------------- |
| 顶栏（shell 注入） | 品类下拉 / 周月切换 / 周期下拉 / 对比下拉          | —             |
| 页面头          | "周月复盘" 标题 + 一句副标题                  | 约 0.5 屏       |
| 复盘范围条        | 周期 + 品类 + 对比 一行                    | 小             |
| **复盘设置**     | 4 个目标输入 + 复盘人 + 状态（**目标未录时默认展开**）  | **约 0.5 屏**   |
| 状态条 ×2       | "还有 5 个必填段落未填写" + "素材已更新・覆盖 1/2 天" | 小             |
| **经营驾驶舱**    | 4 张指标卡（含 AI 洞察行）+ 信号条 + 归因折叠       | **约 0.8 屏**   |
| 4 个 tab      | 复盘结论 / 拆因分析 / 计划与动作 / 数据参考         | —             |
| 业绩全景         | 8 核心 KPI + 5 折叠指标 + 按日明细表          | 约 0.8 屏       |
| **六段写作区**    | 每段 3 个文本框（分析 / 根因 / 下一步）+ 折叠证据     | **从第 3 屏才开始** |

### 1.2 六个核心问题（每项均有证据）

**P1 写作区被推到第 3 屏之后，首屏全是支撑信息**



* 复盘设置默认展开（目标未录时）占约 0.5 屏，驾驶舱占约 0.8 屏，业绩全景再占 0.8 屏，

  用户的核心动作 "写六段结论" 在 1280×800 首屏内完全不可见。

* 页面定位是 "把复盘写完存下来"，但写作任务在视觉和信息层级上都不是主角。

**P2 证据全折叠 + 看写分离，写结论必须来回切 tab**



* 六段中每段的证据是 `展开系统证据（N 个数据块）` 折叠区（实测 N=2/1/2/1/3/1），

  用户不展开就看不到数据；不知道有什么证据，自然也不会展开。

* 想查完整数据要切到 "拆因分析"tab（约 13 屏表格墙），写完再切回来 —— 两件事被硬拆开。

**P3 目标输入与展示口径混乱，数据失去可信度**



* 输入框 "净费比目标 %" 占位提示 "如 23.70"，但驾驶舱卡显示 " 目标 **2370.00%**・完成率

  **6005.2%**"—— 用户按占位符填入的数值与展示口径不一致，且没有任何输入校验 / 范围提示。

* 卡名与输入框命名不一致："账单花费" 卡对应 "推广费目标" 输入、"净销售额" 卡对应

  "销售额目标" 输入，同一指标两套叫法。

* 目标未设置时，完成率卡显示 "—"，但依旧占据核心位置，视觉上是 "坏数据"。

**P4 拆因分析 = 表格墙，缺少提炼引导**



* 4 个锚点 + 7–8 张 TOP10 榜（净销售 / 下滑 / 付费 / 盈利 / 亏损 / 新品 ×2）+ 货品汇总 +

  问题清单（20 个商品、8 列、超长商品名）+ 利润瀑布，约 13 屏。

* 每张榜结构雷同，扫读成本高；用户需要自己跨榜合并信息才能得出结论，页面不提供

  "看完这张表该注意什么" 的引导。

**P5 信息三重重复**



* 周期 / 品类 / 对比 在 "复盘范围" 条、驾驶舱标题、"状态条" 三处重复出现；

* "素材已更新・事实覆盖不完整" 与 "还有 5 个必填段落未填写" 两条状态条叠放，视觉噪声大。

**P6 历史复盘不能直接跳转**



* 点历史列表里的一期，若周期与当前不符，只弹提示 "请到顶栏切到对应周期查看"，

  用户要手动去顶栏翻下拉框 —— 前端已持有该 period\_key，完全可以直接加载。

### 1.3 上一轮已做（不重复做）

9/29 方案 P0–P3 已落地：三大指标完成率卡、tab 归并为 4 个叙事区块、段落三段式 v3、

问题单品聚合、周月互汇、Markdown 导出、竞店深链、排期时间轴、字段设置公共组件化、

拆因锚点 chips、根因内嵌证据。**本方案不做功能回退，只重排信息架构与交互。**

## 2. 重构目标与设计原则



| 原则     | 含义                                         |
| ------ | ------------------------------------------ |
| 任务优先   | "完成一期复盘"= 1 条纵向主流程（结果 → 六段 → 保存），首屏必须看见写作区 |
| 数据服务写作 | 每段内嵌该段关键证据（默认可见），全量数据进侧抽屉，写作时不离开当前段        |
| 一屏一意   | 首屏只做三件事：看结果（HUD）、写结论（六段）、存 / 导出（底部条）       |
| 口径统一   | 输入即所见：百分比输入带 % 后缀与范围校验，卡名与输入框同词            |
| 不砍功能   | 拆因 / 矩阵 / 排期 / 导出全部保留，只是换个位置和呈现密度          |

## 3. 目标信息架构（推荐方案 A：单页纵向流）



```
┌────────────────────────────────────────────────────────────┐
│ 顶栏（不变）：品类 / 周月 / 周期 / 对比                       │
├────────────────────────────────────────────────────────────┤
│ HUD 一行（替代 驾驶舱+设置+双状态条）                        │
│  [周期·品类·对比]  [净销售完成率][净利润完成率][净费比]  [⚙目标] │
│  [风险 n][待动作 n]  [保存状态]                               │
├────────────────────────────────────────────────────────────┤
│ 六段写作区（首屏即达，每段：）                               │
│  ① 品类汇总                                                   │
│     分析□ 根因□ 下一步□      ┊ 证据：三大指标+分周迷你表（可见）│
│  ② 货品复盘   ……             ┊ 证据：净销售TOP5+问题TOP5       │
│  ③ 广告复盘   ……             ┊ 证据：渠道花费/ROI 迷你表        │
│  ④ 市场监控   ……             ┊ 证据：行业/竞店 1 行摘要         │
│  ⑤ 本周总结   ……             ┊                                │
│  ⑥ 下周规划   ……             ┊ 排期条（可编辑）                │
│  每段右下角「查全部 →」打开数据抽屉                             │
├────────────────────────────────────────────────────────────┤
│ 底部：刷新素材 / 导出复盘 / 保存复盘（不变，含必填进度）       │
└────────────────────────────────────────────────────────────┘

数据抽屉（右侧滑出，不遮写作区，替代"拆因分析"tab）：
  [货品][推广][流量][市场] 四锚点
  默认每表 TOP5 + 「展开全部」，行内可开趋势弹窗、生成动作
```

### 3.1 HUD 一行化（替代 1.1 的 "复盘范围条 + 设置 + 双状态条 + 驾驶舱" 四块）



* 第一行左：`2026年10月第1周（10-01~10-04） · 标品袜子 · 环比上期`（只出现一次）。

* 第一行中：三张**迷你完成率卡**（净销售额 / 净利润 / 净费比）：数值 + 完成率 + 环比 / 同比，

  未设目标时显示 "未设目标・点此补录" 小按钮（点击展开目标弹窗），不再显示 "—" 占位。

* 第一行右：`风险 n · 待动作 n`（点击进对应锚点）+ 保存状态。

* 目标 / 复盘人 / 状态：收进「⚙ 复盘设置」弹窗，**默认收起**；弹窗内输入即所见

  （见 4.4），并保留 "草稿 / 已定稿" 切换。

* AI 洞察行（主要问题 / 经营判断 / 投放效率 / 拖累来源）不下沉：保留在对应迷你卡的 tooltip

  或点击展开，避免首屏再堆 4 行文字。

### 3.2 六段写作区上移，证据随文可见



* 每段结构不变（分析 / 根因 / 下一步 三段式），但**该段关键证据默认展开 1–2 个核心块**

  （如货品段展示 "净销售额 TOP5 + 问题商品 TOP5" 精简版），其余证据收进

  `更多证据（N）` 折叠，不再默认全折。

* 每段右下角固定一个「查全部 →」按钮，打开数据抽屉并定位到对应锚点。

* 段落占位符升级为 "写作提示"（见 4.5），降低空白 textarea 的认知负担。

### 3.3 数据抽屉（替代 "拆因分析"tab 的主地位）



* 右侧 60% 宽度滑出，**不遮挡写作区**；四锚点 chips 固定于抽屉顶部，滚动跟随。

* 表格默认压缩：每榜只显示 TOP5 + 行内 "展开全部"；列设置 / 字段开关保留。

* 从任何一段的「查全部」进入时自动定位锚点；也可从底部 "数据档案" 按钮打开。

* 抽屉内保留：问题清单（列精简为 5 列，商品名截断 + title）、趋势弹窗、生成动作、

  市场摘要与深链、流量拆解。

### 3.4 计划与动作：空态优化 + 与写作区相邻



* 无动作时不再显示 4 个 "无排期动作"+ 5 个空状态区堆叠，改为一行空态

  "本期暂无动作，可在货品 / 广告段从问题商品生成" + 一个「生成动作」按钮。

* 有动作时保持现有排期时间轴 + 状态分区。

### 3.5 历史复盘：直接跳转



* 点击历史任一期的按钮逻辑从 "提示去顶栏切周期" 改为 **前端 setMode + 设置**

  **selectedPeriodKey + 同步顶栏范围 + load ()**（后端已支持按 period\_key 加载，

  纯前端改动，见 period-review-live.js `setMode`/`syncRangeToSelectedPeriod`）。

## 5. 分阶段实施

### P1：纯前端布局重排（0.5–1 天，不动后端）



* HUD 一行化：合并范围条 / 设置 / 双状态条 / 驾驶舱；目标弹窗化（默认收起）。

* 六段写作区上移：删除首屏对写作区的压制（KPI 墙收进业绩全景折叠，按日表保留）。

* 每段默认展开核心证据块（先做 ①②③ 三段，④⑤⑥ 保持折叠态但证据数量前置到标题行）。

* 历史复盘直接跳转；状态条去重；问题清单列精简 + 商品名截断。

* **验收**：1280×800 首屏看到 HUD + 六段前两段；切历史任一周期直接加载；

  保存 / 导出 / 草稿恢复行为与现状一致。

### P2：数据抽屉 + 表格压缩（1–2 天）



* 右侧抽屉容器 + 四锚点 + 滚动跟随；原 "拆因分析"tab 的渲染函数改为注入抽屉。

* 各榜默认 TOP5 + 展开全部；列设置浮层适配抽屉宽度。

* 段落「查全部 →」定位锚点；底部 "数据档案" 入口。

* **验收**：写作任意一段时抽屉可开可关、不遮写作区；TOP5 / 展开切换后数据与全量一致；

  趋势弹窗、生成动作、市场深链在抽屉内正常。

### P3（可选，用顺后做）



* 段落 "一键填入关键数字"（从证据块取 TOP 数据拼进 textarea）。

* 净费比目标输入范围校验（如 0–100，超出标红提示 "请按百分比填写"）。

* 移动端 / 窄屏适配抽屉。

## 6. 验收标准（清单）



* [ ] 首屏（1280×800）内可见：HUD 一行 + 六段写作区前两段 + 底部保存条。

* [ ] 周期 / 品类 / 对比在页面中只出现一次；目标弹窗默认收起。

* [ ] 写任意一段时不切 tab 可看到该段核心证据；「查全部」打开抽屉并定位锚点。

* [ ] 目标任意输入后完成率卡数值可读（单位一致，无 2370.00%/6005.2% 类展示）。

* [ ] 点击历史任意一期，直接加载该期复盘（无需手动切顶栏）。

* [ ] 现有功能零回归：保存 / 定稿校验 / 导出 Markdown / 草稿恢复 / 动作生成 / 趋势弹窗 / 周月互汇。

* [ ] 回归：`tests/` 全量 + 浏览器逐项走查（对照 9/29 验收清单）。

## 7. 风险与约束



* **不触碰数据口径**：本方案全部是前端信息架构与交互重排；GSV / 净销售 / 费比等口径、

  `_target_rows` 计算逻辑不动。

* **旧复盘兼容**：段落三段式与保存结构 v3 不变，老复盘打开不丢内容。

* **抽屉与表格宽度**：16 列矩阵等宽表不进抽屉，留在 "数据参考" 区（矩阵可横向滚动），

  抽屉只放榜单 / 清单类表格。

* **AI 洞察文案**：维持 "系统观察不代替经营结论" 纪律，只移动位置，不新增生成逻辑。

## 8. 待用户拍板的决策点



1. **布局方向**：A）单页纵向流 + 数据抽屉（本方案推荐）；B）保留四 tab，仅把写作区

   提前 + 证据默认展开（改动更小，但看写分离问题仍在）。

2. **拆因数据放哪**：侧抽屉（推荐，写作时不离开当前段）vs 页面下方下沉区（长滚动）。

3. **净费比目标口径**：历史已存值按 "百分比" 展示（23.7 显示 23.70%）还是维持现状

   （2370 显示 2370.00%），以及新输入是否加 0–100 校验。
