# TM 数据能力与页面体系设计

**日期**：2026-08-14  
**范围**：当前单店 `dashboard.db` 与 `source.xlsx` 能真实支撑的经营闭环  
**状态**：设计基线，未进入实现

## 1. 背景与目标

当前项目已经包含数据概览、商品运营、推广分析、生命周期、周期对比、经营目标、经营复盘、数据中心、设置和管理工作台等页面，但数据事实、派生指标、业务状态和操作记录存在重复模型。旧动作表 `operation_actions` 与新动作表 `product_actions` 并存，主导航也没有覆盖全部业务页面。

本设计的目标是建立一套可验证的页面体系：

1. 先明确当前实际可取得的数据，再决定页面能力。
2. 统一指标计算和数据充分性表达，页面不自行猜测字段含义。
3. 让页面围绕“发现问题 → 定位对象 → 执行动作 → 观察结果 → 复盘沉淀”形成闭环。
4. 将详情、编辑、配置和流程操作分成不同弹层类型。
5. 为后续多店、多源市场数据保留扩展边界，但不让空数据制造虚假能力。

## 3. 数据分层

### 3.1 事实层

事实层只保存外部报表或系统导入的原始经营事实：店铺日度、商品日/月/周度、推广日度、评价、关键词、商品主数据和导入批次。原始列名保留在导入记录中，业务接口使用字段字典中的标准键。

### 3.2 指标层

指标层由唯一计算入口生成，页面不得重复实现公式。核心公式如下：

```text
net_sales = sum(payment_amount) - sum(successful_refund_amount)
refund_rate = sum(successful_refund_amount) / sum(payment_amount)
payment_conversion_rate = sum(payment_buyers) / sum(product_visitors)
average_order_value = sum(payment_amount) / sum(payment_buyers)
ad_roi = sum(attributed_payment_amount) / sum(ad_spend)
expense_ratio = sum(ad_spend) / sum(payment_amount)
returning_buyer_ratio = sum(returning_payment_buyers) / sum(payment_buyers)
```

比率和 ROI 必须先汇总分子、分母再计算，不能平均原始行比率。除数为零或依赖字段缺失时返回不可计算状态。

### 3.3 状态层

状态层描述数据和经营对象当前能否支持操作：

- 数据：`available`、`no-data`、`insufficient-data`、`missing-fields`、`partial`、`source-unavailable`、`calculation-failed`。
- 商品：在线、下架、清退等业务状态。
- 健康度：优秀、良好、关注、预警。
- 生命周期：新品、成长、爆发、成熟、衰退、清退，以及数据积累中。
- 目标：进行中、达成、落后、锁定。
- 告警：待处理、已忽略、已关闭。

### 3.4 动作层

新增动作只使用 `product_actions`：

```text
草稿 → 待执行 → 执行中 → 观察中 → 待复盘 → 已完成
```

异常状态为 `阻塞`、`计算失败`、`已取消`。每个动作必须绑定商品、目的、目标指标、计划时间、观察窗口、前值、后值、结果和复盘结论。旧 `operation_actions` 只读兼容，不再产生新数据。

## 4. 能力分档

### 4.1 可直接提供

店铺经营总览、商品排行和趋势、商品筛选与字段模板、基础推广分析、目标管理、生命周期基础评估、动作状态机、导入预览/确认/撤销/审计、评价基础分析。

### 4.2 依赖数据充分性

新老客结构、访客到支付漏斗、健康度、生命周期季节属性、推广多粒度下钻、行业 Benchmark、评价代表性分析和市场关键词洞察。页面必须展示缺失字段、缺失日期或样本不足原因。

### 4.3 当前不承诺

毛利/利润、库存与周转、用户级 cohort/留存、严格因果归因、完整市场机会榜。当前数据没有对应的成本、库存、用户明细或市场事实。

## 5. 页面职责与交互边界

| 页面 | 核心问题 | 输入 | 主要操作 | 弹层 |
|---|---|---|---|---|
| 数据中心 | 数据能不能信 | 文件、字段字典、导入批次 | 预览、修映射、确认、撤销、审计 | 导入确认、撤销确认、审计详情 |
| 数据概览 | 店铺最近发生了什么 | 店铺日度、商品汇总、目标、告警、动作、事件 | 日期/对比、KPI 下钻、报告、导出、事件 | 图表事件编辑 |
| 商品运营 | 哪些商品需要处理 | 商品主数据、月/周事实、健康度、标签、备注、动作 | 搜索、筛选、排序、模板、批量标签、备注、动作、导出 | 列设置、商品详情抽屉、批量确认 |
| 商品详情 | 单个商品为什么变化 | 单品趋势、推广、评价、生命周期、动作历史 | 指标切换、创建动作、查看历史、备注/标签 | 动作创建、动作复盘 |
| 推广分析 | 钱花在哪里且是否有效 | 推广日度事实、商品主数据、字段模板 | 粒度筛选、下钻、模板、导出 | 下钻抽屉、字段设置 |
| 生命周期 | 商品处于什么阶段 | 商品月度、主数据、生命周期档案/历史 | 阶段筛选、趋势、人工调整、锁定、导出 | 生命周期详情、人工调整 |
| 周期对比 | 两个周期差异在哪里 | 两个自然月的统一指标 DTO | 选择周期、指标切换、导出 | 无 |
| 经营目标 | 目标是否按计划推进 | 年度目标、周期目标、锁定和版本 | 建议、生成、调整、锁定、审计 | 调整确认、锁定冲突确认 |
| 经营复盘 | 哪个动作是否有效 | 统一动作、历史、周期复盘、事实指标 | 状态筛选、观察窗口重算、迁移、复盘 | 状态迁移确认、动作复盘 |
| 设置 | 口径和模板怎么管理 | 字段/枚举字典、视图模板、店铺配置 | 配置、字典、模板 | 字典编辑、影响范围确认 |
| 管理工作台 | 谁负责什么及何时执行 | 任务、人员 KPI、调度、日志 | CRUD、手动运行、查日志 | 新建任务、KPI、调度 |

管理工作台属于管理域，不应承载经营指标解释；后续可作为管理入口或并入设置/数据中心的管理区。

## 6. 弹层规范

弹层只允许四类：

1. **详情型**：只读证据和下钻结果，不包含修改动作。
2. **编辑型**：修改明确实体，显示旧值、新值、操作者和原因。
3. **配置型**：修改模板或字典，显示作用范围和影响页面。
4. **流程型**：导入、撤销、状态迁移、锁定和复盘等有副作用操作，必须显示影响范围、失败处理和是否可撤销。

所有弹层统一支持键盘关闭、焦点回收、加载、无数据、缺字段、部分成功和失败状态。

## 7. 跨页面闭环

```text
数据中心导入
  → 更新来源批次和数据状态
  → 数据概览发现异常
  → 商品运营定位商品
  → 商品详情/推广/生命周期解释原因
  → 创建运营动作
  → 经营复盘观察和回算
  → 结论沉淀到标签、周期复盘和下一动作
```

跨页跳转必须携带条件：

- 概览异常 → 商品运营：指标、日期、异常商品筛选。
- 商品运营 → 推广分析：`product_id`。
- 商品运营 → 生命周期：商品和阶段。
- 商品详情 → 经营复盘：商品动作。
- 目标进度 → 概览：目标周期。
- 导入批次 → 受影响页面：来源批次和缺失日期。

## 8. 统一 API 上下文

所有新业务接口沿用统一 envelope，并增加能力声明：

```json
{
  "ok": true,
  "data": {},
  "availability": "available",
  "capabilities": {
    "can_export": true,
    "can_drilldown": true,
    "can_edit": false,
    "can_create_action": true
  },
  "filters": {},
  "missing_fields": [],
  "missing_ranges": [],
  "source_batches": [],
  "requestId": "..."
}
```

前端不能通过字段是否存在来猜测能力，必须依据 `availability` 和 `capabilities` 决定按钮、弹层和空状态。

## 9. 导航结构建议

核心导航保留七个一级域：

1. 数据概览
2. 商品运营
3. 推广分析
4. 生命周期
5. 经营复盘
6. 数据中心
7. 设置

经营目标、周期对比和商品详情作为从核心页面进入的上下文页面；管理工作台作为管理入口，不与经营分析页面并列。所有上下文页面必须支持返回来源页并保留筛选条件。

## 10. 验收矩阵

### 数据口径

- 同一日期范围内，概览、商品、推广和导出使用同一标准字段名和公式。
- 比率/ROI 使用汇总后计算，除零和缺字段返回明确状态。
- 每个结果可追溯到来源批次和缺失日期。

### 页面能力

- 每个页面能在 `available`、`no-data`、`insufficient-data`、`missing-fields`、`partial`、`calculation-failed` 下稳定渲染。
- 无数据时不显示伪造的排名、机会或结论。
- 页面跳转保留日期、商品、分层、渠道和对比条件。

### 动作闭环

- 新动作只写入 `product_actions`。
- 状态迁移有合法路径、操作人、时间和审计记录。
- 观察窗口不足、重叠或失败时不生成有效结论。

### 弹层

- 详情、编辑、配置、流程四类弹层有明确边界。
- 流程型弹层显示影响范围和可撤销性。
- 移动端和桌面端均可关闭、回收焦点并显示失败原因。

## 11. 范围与风险

- 本设计不新增市场、利润、库存或用户明细数据源。
- 多店和多源市场分析需要在后续补充事实表、店铺维度和权限模型后再进入设计。
- 当前评价和市场数据样本有限，相关页面必须以样本量和数据状态为前提。
- 旧接口保留兼容，但新页面不得依赖含义不明确的旧字段别名。
