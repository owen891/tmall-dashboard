# 统一详情与配置设计

## 目标

把当前分散的商品详情、字段模板和预警规则收敛为一次详情交互、一个配置真相源和一条可验证的规则执行链路。

## 现状问题

1. 商品页先打开窄抽屉，再进入独立详情页；推广页也先展示轻量明细，再跳商品详情，核心信息被拆成重复下钻。
2. 商品字段模板通过 `/api/settings` 持久化，推广字段模板只保存在浏览器本地，界面文案却都叫“保存为模板”。
3. `alert_rules` 表和旧接口已存在，但推广服务仍使用写死的 ROI 阈值，配置无法影响页面结果。
4. 商品、推广、导入、设置和字段文档分别维护字段键、标签和格式，别名已经进入业务层。
5. 设置页默认商品视图使用固定选项，无法正确展示自定义模板。

## 设计决策

### 一次完整详情

- 商品列表“详情”、推广商品“明细”和推广预警“查看商品”都打开同一个大型原生 `dialog`。
- 弹窗一次加载并展示：商品基本信息、经营 KPI、推广 KPI、日趋势、生命周期、备注、标签和运营动作。
- 推广入口把当前推广行作为上下文传入，弹窗优先展示推广指标，但不再增加第二次下钻。
- `/products/:productId` 保留为兼容深链接，不再作为正常操作链路入口。
- 生命周期现有完整详情弹窗保持不变；管理页表单、数据工具箱等任务型弹窗不改成详情弹窗。

### 统一配置真相源

- `/api/settings` 是模板定义的唯一持久化来源。
- 商品模板继续使用 `view_templates`；推广模板新增 `promotion_view_templates`，按 `products/keywords/crowd/site` 分组。
- 浏览器本地只保存当前页面最后使用的模板和临时列选择，不再保存模板定义。
- 首次加载时如发现旧推广本地模板而服务端没有对应模板，执行一次兼容迁移，迁移成功后不再依赖旧存储。
- 设置页的默认商品视图选项从 `view_templates` 动态生成，支持自定义模板往返保存。

### 统一字段目录

- 新建服务端字段目录，结构固定为 `{key, label, domain, source_type, group, format, aliases}`。
- 商品、推广、导入映射和设置页从同一目录读取允许字段和展示元数据。
- `conversion`、`refund_amount`、`attributed_payment_amount` 等旧名只允许在 API/导入适配边界转换为标准键，不能继续扩散到配置定义。
- 字段目录通过只读设置元数据接口返回，业务页面不直接读取数据库列名。

### 可配置预警规则

- 预警规则使用独立 repository/service/blueprint，不再把新逻辑继续堆进 `api/data_api.py`。
- 规则字段为：名称、作用域、指标、运算符、阈值、级别、启用状态。
- 首期作用域只支持 `store` 和 `promotion_product`，不实现复杂规则编排。
- 推广服务按 `promotion_product` 规则逐商品计算；同一商品同一指标命中多条规则时只返回最高级别结果。
- 设置页提供统一规则管理；推广页提供“配置预警”快捷入口，复用同一规则编辑组件和 API。
- 现有硬编码 ROI 安全线迁移为两条默认规则：ROI `< 3` 为 warning，ROI `< 1.5` 为 danger。

## 数据流

```text
设置页/推广快捷入口
  -> /api/alert-rules 或 /api/settings
  -> service 校验
  -> repository/SQLite
  -> promotion service 读取规则并计算
  -> /api/promotion 返回 alerts
  -> 推广页展示命中原因

商品页/推广页详情按钮
  -> shared product detail dialog
  -> /api/products/:id/detail + notes/tags/actions
  -> 一次渲染完整信息和写操作
```

## 错误与状态

- 所有配置写入显示 saving/success/error 状态，失败时保留用户输入。
- 详情弹窗区分加载、无数据、部分数据和请求失败；推广数据失败不阻断商品基础详情。
- 保存模板、规则和运营动作都由服务端返回统一 envelope 与校验错误。
- 弹窗支持 Escape、遮罩关闭、焦点进入和回退；内部内容独立滚动，移动端占满可用视口。

## 验证标准

1. 商品和推广入口均只需一次点击即可看到完整详情，不出现“打开完整详情页”。
2. 推广模板保存后刷新、换页面和重新打开浏览器仍存在，并可删除、应用。
3. 自定义商品模板可以在设置页被选为默认值并正确往返保存。
4. 新增或修改预警规则后，`/api/promotion` 的预警结果立即按规则变化。
5. 字段目录中的标准键被设置、商品、推广和导入共同消费。
6. 桌面与 390px 视口下弹窗无不可恢复溢出，键盘操作完整。

## 范围边界

- 保留 Flask、SQLite 和原生 HTML/CSS/JavaScript。
- 不增加新的前端框架或依赖。
- 不实现多店铺、复杂规则编排、通知渠道或审批流。
- 不提交 Git；所有改动保持在当前工作区供检查。
