# README 截图化重构设计

**日期：** 2026-08-16
**状态：** 已确认
**范围：** GitHub 仓库 README 与配套截图资产

## 目标

把 README 从长篇验收记录重构为可快速理解、可部署、可验证的产品入口。首屏必须让读者看到真实应用界面，并在两分钟内回答以下问题：

1. 这是什么产品，适合谁使用。
2. 当前 `1.0.0` 能解决哪些商品运营和数据治理问题。
3. 如何安装、启动和升级。
4. 数据来源如何取舍，哪些限制仍未解决。

## 信息架构

采用“产品叙事型”单列结构：

1. 产品名称、版本徽章、简短定位和 Release 入口。
2. 总览页宽幅主截图，作为第一视觉信号。
3. 核心能力表，压缩说明数据治理、商品运营、数据接入和审计能力。
4. 商品运营与数据中心双截图，分别说明业务操作和数据治理。
5. 数据来源优先级说明：生意参谋和推广工具为重复字段主来源，DMP 为参考、缺失补充和独有字段来源。
6. 快速开始、生产启动和定时扫描命令。
7. 验证结果、已知限制和详细文档链接。

原 README 中过长的 PRD 验收矩阵不再完整展示，只保留验证摘要并链接到 `docs/PRD_KEEP_EXISTING_ARCHITECTURE.md`。发布细节链接到 `docs/RELEASE_STATUS.md` 和 GitHub Release。

## 截图设计

提交三张真实应用截图：

| 文件 | 页面 | 作用 |
|---|---|---|
| `docs/assets/readme/overview.png` | 总览 | 展示核心经营指标、趋势和运营工作台整体结构 |
| `docs/assets/readme/products.png` | 商品运营 | 展示商品列表、筛选、字段配置和运营动作入口 |
| `docs/assets/readme/data-center.png` | 数据中心 | 展示导入、字段映射、数据能力和来源治理 |

截图统一使用 `1440x900` 桌面视口，保留完整应用壳层和第一屏核心内容，不截浏览器地址栏。README 中总览图全宽展示，商品运营和数据中心使用并列 HTML 表格；GitHub 窄屏下允许自然缩放。

## 数据安全

- 截图只使用 `scripts/seed_demo_data.py` 生成的独立演示数据库。
- 不读取或复制生产库到截图目录，不展示真实经营数据、路径、账号或凭据。
- 截图资产只包含页面像素，不包含数据库、日志或导入源文件。
- 页面若出现本地绝对路径、真实扫描目录或生产文件名，截图前替换为演示值。

## 采集与验证

1. 启动指向演示数据库的本地测试服务。
2. 使用 Playwright 访问总览、商品运营和数据中心页面。
3. 等待 API 数据和图表渲染完成后截图。
4. 检查图片尺寸、非空像素、文字截断、弹窗遮挡、横向溢出和敏感信息。
5. 运行 Markdown 链接检查、`git diff --check` 和 UI 静态门禁。

## 完成标准

- GitHub 能正确渲染三张截图，路径不依赖分支绝对 URL。
- README 首屏包含产品定位、版本和总览截图。
- README 不重复整份 PRD，不使用过期测试数字。
- 快速启动命令和 Release 链接可直接使用。
- 已知的 5,674 条无可信血缘历史事实仍明确标记为生产数据阻断。
