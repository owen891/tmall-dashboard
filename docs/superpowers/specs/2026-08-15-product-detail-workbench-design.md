# 商品详情三级工作台设计

## 目标

将商品详情从“列表内的完整弹窗”调整为真正的三级下钻页面：

`商品经营` -> `商品列表` -> `商品详情 /products/<product_id>`

详情页承载单品的完整经营分析、生命周期判断、运营动作闭环和数据证据；弹窗只保留快速预览，不再承担完整详情工作台的职责。

## 已确认的视觉方向

- 延续现有 `frontend/ui_demo/assets/tokens.css` 和 `shell.css`。
- 页面底色使用 `--surface-page`，内容面板使用 `--surface-base`。
- 品牌主色使用 `--brand`（当前为橙色 `#e4400f`）。
- 灰阶承担文字、边框和层级；蓝、绿仅表达图表和状态。
- 不新增“商品详情”一级侧栏导航，详情页沿用商品经营的当前导航项。

## 页面结构

1. 全局壳层：现有侧栏和顶部栏，当前导航为“商品经营”。
2. 上下文栏：面包屑、商品标题、商品 ID、状态、更新时间。
3. 页面动作：返回商品列表、导出详情、新建运营动作、上一商品/下一商品。
4. KPI 首屏：净销售额、支付转化率、推广 ROI、商品访客、生命周期。
5. 详情分组：经营概览、日度趋势、生命周期、运营动作、数据证据。
6. 概览内容：趋势图、异常提醒、系统建议、当前判断和待办动作。

## 交互与状态

- 商品列表点击商品名称或“详情”默认跳转到 `/products/<product_id>`。
- 跳转时保留列表筛选条件、页码和必要的返回上下文；返回列表后可恢复。
- 详情页继续使用 `/api/products/<product_id>/detail`，日期范围通过 `start` 和 `end` 查询参数传递。
- 导出继续使用 `/api/products/<product_id>/detail/export`，与页面当前日期范围一致。
- 首次加载、无数据、字段缺失、请求失败和权限不可用都显示明确的页面状态；不使用静默空白。
- 弹窗快速预览可以继续调用同一详情接口，并提供“打开完整工作台”链接；不得复制一套指标计算逻辑。

## 实现边界

- 优先调整正式 demo 页面、商品列表跳转行为和共享详情适配器。
- 不改动商品详情 API 的字段契约，不新增依赖，不新增一级导航。
- 旧版 `templates/dashboard.html` 兼容入口保持不变。

## 验证

- 现有商品详情 API 测试继续通过。
- 增加或更新导航契约，覆盖列表到详情的 URL 跳转和返回上下文。
- 对 `/products/<id>` 做桌面和移动端烟测，确认无横向溢出、加载状态可见、导出链接正确。
- 运行前端静态门禁、Python 测试和生产预检。
