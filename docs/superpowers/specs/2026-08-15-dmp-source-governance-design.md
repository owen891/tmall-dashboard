# DMP 多源数据治理设计

## 目标

将 DMP 全店单品日度文件纳入 TM 的多源数据合同：生意参谋负责商品交易和主流量，推广工具负责推广事实，DMP 作为参考来源；主来源缺失时，DMP 按字段回退补齐，DMP 独有字段可以生效。

## 已确认数据

文件 `全店单品列表_本店_2026-05-03 23_16_34_226638_1777821435303.xlsx` 为商品日度数据，包含 15,157 条明细、569 个商品、2026-04-01 至 2026-04-30 的 23 个字段。重复字段集中在支付金额、IPV、支付转化率和推广指标；搜索/推荐流量、预售、复购和连带购买字段主要由 DMP 提供。

## 设计决策

1. 按 `商品 + 日期 + 标准字段` 做字段级裁决，不按整张文件覆盖。
2. 保留原始观测、最终生效值和字段血缘。
3. 生意参谋优先交易和商品主流量；推广工具优先推广事实；DMP 只在主来源缺失时补齐。
4. DMP 独有字段无其他稳定来源时可以正式生效，但页面必须显示 DMP 来源。
5. 主来源为 0 时不触发回退；只有空值、无效值和解析失败才算缺失。
6. 比率、ROI、单价优先由分子/分母重算，禁止简单平均。

## 交互和审计

导入预览显示各来源值、最终值和裁决原因；结果状态包括 `primary_kept`、`fallback_filled`、`reference_only`、`effective_unique` 和 `conflict`。商品页、推广页和导出均使用最终生效值，并提供来源批次和原始值追溯。

## 质量门禁

DMP 的总计行、空商品 ID、空日期不得进入商品事实；`-` 和 `--` 视为缺失；百分比必须归一化并进行范围检查。可选比例异常采用字段级隔离：保留同一行其他有效字段，异常字段不写观测和有效血缘，不截断为 100%，报告记录字段告警。必填字段错误和重复业务键仍阻断导入。报告记录剔除行、字段告警数、冲突数、补齐数、参考字段数和幂等结果。

`daily_data`、来源观测、字段血缘和对账结果统一使用 `shop_id + product_id + date` 业务粒度。历史事实迁移到 `default` 店铺；不同店铺同商品同日期必须共存，批次撤销按店铺重建事实。

真实文件验收基线：15,158 条原始行，剔除 1 条汇总行，15,157 条有效商品日明细，569 个商品，日期范围 2026-04-01 至 2026-04-30，重复业务键 0；当前样本存在 34 个异常比例字段，均应形成字段告警且不阻断确认。

## 非目标

本次不改变现有 Flask、SQLite、原生 JavaScript 架构，不让 DMP 覆盖生意参谋或推广工具，也不从 DMP 缺失字段反推退款、支付买家数或店铺去重客户数。
