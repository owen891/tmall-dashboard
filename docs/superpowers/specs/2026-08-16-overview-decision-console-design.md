# 数据概览经营决策台 Demo 设计

## 状态

已确认方向：A「经营决策台」。本 spec 只覆盖第一个评审 demo，后续全量页面在该 demo 验收后再展开。

## 目标

把「数据概览」从指标堆叠改成单店运营者可以连续完成的工作面：先知道本期结果和最大偏差，再看到证据，最后能进入动作、商品或复盘。视觉升级使用 TM 2.0 的冷灰、白色和紫色体系，不改变现有业务口径、API 合同和写入流程。

## 现状依据

- 项目使用 Flask + SQLite + 原生 HTML/CSS/JavaScript，不引入新的前端框架。
- 现有 `frontend/ui_demo/pages/overview.html` 已接通数据上下文、目标、KPI、趋势、动作、异常、日度矩阵、重点商品和经营报告。
- 现有 `frontend/ui_demo/assets/overview-live.js` 已复用 `/api/overview`、`/api/trend`、`/api/products`、`/api/target_progress`、`/api/anomalies`、`/api/compare`、`/api/report` 和日度矩阵接口。
- 现有数据层已经区分不可用、数据不足、空结果和请求失败；demo 不补造 0，不把缺失字段伪装成正常值。
- 当前工作区有大量未提交改动。本次只增加隔离 demo 文件和本 spec，不回滚或重排其他改动。

## 范围

### 包含

1. 一个独立的 `frontend/ui_demo/pages/refactor-overview-v3.html` 评审页。
2. 一个独立的页面样式文件，消费现有基础 token 和组件样式，并局部覆盖 TM 2.0 配色。
3. 一个独立的页面控制脚本，优先复用现有 `DemoApi`、图表能力和状态约定。
4. 桌面、平板、手机三个视口的可用布局和最小交互：日期切换、KPI 驱动趋势、目标详情、动作/异常下钻、矩阵横向查看和导出。
5. 可验证的加载中、成功、空数据、数据不足、接口失败和重试状态。

### 不包含

- 不修改 Flask API、SQLite schema、现有生产页面或数据计算公式。
- 不在本轮扩展商品、推广、生命周期、复盘、数据中心、设置和商品详情页面。
- 不新增依赖，不更换 ECharts，不改全局品牌 token，避免影响现有橙色页面。
- 不引入综合健康分、自动生成运营动作或未被数据支持的归因结论。

## 信息架构

页面从上到下固定为以下层级：

1. **全局上下文栏**：店铺、日期范围、数据截至、覆盖天数、质量状态、刷新和导入入口。
2. **经营判断带**：一句当前结论 + 净销售额、目标完成度、待处理动作三个决策摘要。
3. **核心 KPI**：净销售额、支付金额、商品支付转化率、商品访客数四项首屏指标；推广花费、推广 ROI、退款率、费比通过“更多经营指标”展开。
4. **决策工作区**：左侧为单指标或最多三指标趋势，右侧为周/月/季度/年度目标进度。
5. **执行工作区**：运营动作待办与异常监控并列，状态、日期、影响指标和下钻入口同一行表达。
6. **证据区**：日度经营矩阵支持横向查看、来源批次追溯和当前结果导出；重点商品和经营报告作为底部摘要。

信息优先级是“结论 > 目标偏差 > 证据 > 动作细节”，但不隐藏现有数据能力。矩阵和更多 KPI 采用渐进披露，减少首屏噪音。

## 组件和边界

- `refactor-overview-v3.html` 负责语义结构、数据属性和可访问标签。
- `overview-decision-demo.css` 负责 demo 独有的布局和局部 token，不复制整套 shell。
- `overview-decision-demo.js` 负责请求编排、状态渲染、趋势选择、重试和下钻事件；数据请求与展示节点分离。
- 现有 `tokens.css`、`shell.css`、`components.css`、`api.js`、`charts.js`、`shell.js` 继续作为基础依赖。
- 交互控件使用原生 button、select、details、dialog 或现有组件约定；图标沿用项目已安装的 Lucide 资源。

## 数据流和状态

页面初始化读取全局周期状态，再并行请求总览、趋势、重点商品、目标、异常、对比和报告；日度矩阵单独请求，避免矩阵慢请求阻塞决策区首屏。每次周期变化生成请求 token，旧响应不得覆盖新周期。

每个模块至少有四种可见状态：加载中、数据可用、无数据/数据不足、请求失败可重试。所有状态都保留模块标题和数据边界说明。接口返回的 `availability`、`unknowns`、来源批次和覆盖信息在上下文或模块内展示，不在前端重新推断。

## 交互验收

- 点击单个 KPI 后，趋势切换为该指标；指标对比最多选择三个，选择状态有键盘焦点和可见反馈。
- 目标进度显示周期、当前值、目标值、完成度和偏差；“目标详情”进入现有目标页。
- 动作和异常只做真实下钻，不由异常自动创建动作；缺少动作数据时显示明确空态。
- 矩阵在窄屏保持表格可读性，通过横向滚动查看，不强行压缩列。
- 刷新、重试、导出和下钻按钮有 hover、active、focus-visible、disabled 状态。
- 390px 下侧栏遵循现有移动导航模式，顶部上下文和操作不互相遮挡。

## 验收与测试

1. `node --check` 通过新增页面脚本。
2. 现有 `scripts/validate_ui_demos.cjs` 不出现新增静态门禁错误。
3. 浏览器在 1440x900、1024x768、390x844 下截图无控制台错误、无不可恢复横向溢出、图表有像素输出。
4. 手动验证至少包含：周期变化、KPI 单选、趋势最多三选、接口失败重试、空动作、矩阵横向滚动和导出链接。
5. 确认 git diff 只包含新增 demo/spec 文件，不触碰用户已有未提交修改。
