# 经营复盘、数据中心、设置重构设计

**日期**：2026-08-14  
**状态**：设计稿已确认，待实现计划  
**范围**：`frontend/ui_demo/pages/reviews.html`、`data-center.html`、`settings.html` 及其对应原生 JavaScript；不迁移 Flask、SQLite、现有 API 或前端框架。

## 1. 目标

将三个一级页面从“功能堆叠的长页面”重构为职责清晰、可追溯、可连续操作的经营后台：

- 经营复盘回答“哪些动作有效、为什么、下一步是什么”。
- 数据中心回答“数据能不能信、导入是否安全、哪个批次影响了页面”。
- 设置回答“店铺口径、模板、字典和预警规则如何维护”。

三页共用现有亮色运营后台视觉语言：`#f7f8fa` 页面底、白色面板、橙红品牌色 `#e4400f`、220px 侧栏、56px 顶栏、4/6/8px 圆角、轻阴影、紧凑表格。

## 2. 现状与问题

当前页面和 API 能力已经覆盖动作状态机、周期复盘、导入预览/确认/撤销、数据能力地图、店铺设置、字段映射、视图模板、分类字典和预警规则，但信息层级不匹配：

- 复盘页首屏先展示完整状态机，再展示周期复盘；待复盘动作、证据、结论填写路径过长。
- 数据中心把上传、字段映射、质量预览、批次历史和能力审计同时铺开，用户无法快速判断当前导入卡在哪一步。
- 设置页把基础配置、模板、字典和规则堆进一个连续表单，缺少范围提示、脏状态和分区导航。
- 三页缺少统一的“摘要 → 主工作区 → 次级证据”结构，跨页跳转容易丢失 `product_id`、日期范围和批次上下文。

## 3. 设计决策

采用 A 方向“同壳分区 + 工作流主区”：保留现有 shell 和组件样式，在页面内部重排职责；吸收数据中心的密集表格和设置页的左树右表结构，不引入新的 UI 框架或依赖。

### 3.1 共用页面结构

```text
固定侧栏（220px）
  └─ 一级导航
固定顶栏（56px）
  ├─ 页面标题与上下文
  ├─ 周期/店铺筛选（按页面决定是否显示）
  └─ 页面级主要操作
内容区（max-width 1500px）
  ├─ 4 个摘要指标卡
  ├─ 主工作区
  └─ 次级证据/历史/说明
```

摘要卡只展示当前页面最关键的状态，不承载复杂编辑。复杂操作使用页面内 panel、抽屉或 dialog，并遵守已有 `detail / edit / config / flow` 分类。

### 3.2 经营复盘

#### 首屏

摘要卡：待复盘动作、观察中、阻塞、数据覆盖率。主工作区默认筛选 `pending_review`，提供状态 chips、刷新和“重新计算观察窗口”。

动作表至少包含：商品/目的、动作前后指标、系统回算结果、证据/干扰因素、状态、操作。行点击打开动作复盘抽屉，抽屉显示来源批次、观察窗口、前后值和历史版本。

#### 交互

- 复盘保存前校验是否有效、原因、结论、后续动作和复盘人。
- 重新计算先展示影响预览；数据覆盖不足时保持 `observing` 或 `calculation_failed`，明确缺失日期和原因。
- 周期复盘改为同页次级 panel，支持日/周/月键，和动作复盘使用不同数据域。
- 从商品、推广或数据批次跳转时携带 `product_id`、`action_id`、`date_range`、`batch_id`，返回后恢复筛选。

### 3.3 数据中心

#### 首屏

摘要卡：可用数据域、部分可用数据域、待确认批次、最新数据日期。导入工作区使用四步 stepper：

```text
上传 → 字段映射 → 质量校验 → 确认入库
```

字段表展示源列、标准字段、推断类型、匹配状态和样例。质量区展示有效/无效行、日期范围、重复键、预计新增/更新和前 25 条异常。

#### 交互

- 预览阶段不得写正式事实表。
- 必填字段缺失、重复业务键或质量门禁未通过时，确认按钮禁用并说明原因。
- 确认后展示批次报告：批次 ID、来源类型、文件名、SHA-256 摘要、日期范围、新增/更新/跳过/无效行数、完成时间和审计入口。
- 批次历史支持查看报告、撤销和跳转受影响页面；后续覆盖时撤销返回 409，不做静默部分回滚。
- 数据能力地图降为次级视图，继续读取 `/api/data-capabilities` 和 `/api/page-capabilities`，但不抢导入主流程的首屏焦点。

### 3.4 设置

设置页内部采用左树右编辑区：

```text
店铺配置
字段映射模板
商品视图模板
分类字典
预警规则
操作审计
```

右侧编辑区提供标题、作用范围、表单/表格、影响页面说明和底部保存操作。保存时显示 dirty 状态、成功/失败状态和恢复默认入口。

- 店铺配置维护店铺名称、时区、货币、自然周起始日、年度目标和生命周期窗口。
- 字段映射、商品/推广视图模板均使用结构化控件；内置模板不可删除，用户模板支持新增、重命名、删除和设为默认。
- 分类字典支持中文名称、启用/停用和系统项保护。
- 预警规则维护名称、作用域、指标、运算符、阈值、级别和启用状态；展示影响页面。
- 核心指标公式保持只读，不提供 JSON 编辑器。

## 4. 状态与错误处理

所有页面继续使用现有统一 envelope 和可用性状态：`available`、`partial`、`no-data`、`insufficient-data`、`missing-fields`、`source-unavailable`、`calculation-failed`。

- `loading`：用骨架或明确加载文案，不显示空白区域。
- `no-data`：说明没有数据的原因和可执行入口，不显示伪造图表或零值。
- `missing-fields`：指出字段、来源和影响页面；相关操作保持禁用。
- `partial`：显示已覆盖范围、缺失日期和受限能力。
- `calculation-failed`：保留原始输入和错误原因，允许重试或返回上一步。
- 所有 dialog/drawer 支持键盘关闭、焦点回收、错误状态和移动端滚动。

## 5. 组件与代码边界

保持原生 HTML/CSS/JavaScript。页面文件只负责结构和挂载点；页面脚本负责状态协调；数据请求继续通过 `DemoApi.domainRequest`；标签和字典继续通过 `DemoLabels`；共享 shell、导航、日期和 modal 规则不复制到页面脚本。

建议新增/复用的前端边界：

- `review-workbench`：摘要、状态筛选、动作表、复盘抽屉、周期复盘 panel。
- `import-workflow`：stepper、字段映射预览、质量门禁、批次报告和撤销。
- `settings-workbench`：设置树、结构化模板编辑器、字典编辑器、预警规则编辑器。
- 现有 API、service、repo 不新增重复公式；页面根据 `availability` 和 `capabilities` 决定按钮状态。

## 6. 响应式与可访问性

- 320px、768px、1024px、1440px 四档验证。
- 760px 以下侧栏收缩，1000px 以下双列降为单列；表格保持横向滚动。
- 图标按钮必须有 `aria-label`；表单控件有可见 label；状态不只靠颜色表达。
- 主要操作、筛选、抽屉关闭和表格操作均可 Tab/Enter 使用。

## 7. 验收标准

1. 三页均使用同一 shell 和现有 token，不出现渐变、紫色主导、大圆角或新视觉主题。
2. 经营复盘默认进入待复盘队列，动作复盘和周期复盘分区明确，结果不足时不伪造结论。
3. 数据中心按上传、映射、质量、确认四步工作；门禁不通过时确认按钮不可执行，批次报告和撤销可追溯。
4. 设置页支持左树导航和结构化编辑，模板、字典、规则保存后刷新仍可恢复；核心公式只读。
5. 跨页跳转保留 `product_id`、`action_id`、`date_range`、`batch_id` 等上下文。
6. 现有 API/服务测试保持通过；新增页面交互测试覆盖加载、空状态、错误状态、门禁和焦点回收。
7. 静态 demo：`/demo/pages/refactor-a-demo.html`，用于实现前确认页面结构，不作为正式业务入口。

## 8. 非目标

- 不迁移 Flask、SQLite、原生 JavaScript 架构。
- 不在本阶段新增固定目录扫描或 AI 采集入库。
- 不新增利润、库存、用户 cohort 或完整市场 benchmark 数据域。
- 不删除旧兼容 API；正式页面不再依赖未登记的旧能力。
