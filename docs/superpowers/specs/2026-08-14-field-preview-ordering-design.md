# 字段预览与排序设计

## 目标

统一商品运营与推广分析的字段设置交互，将“选择字段”和“调整顺序”拆分为两个清晰区域，避免用户把字段行内箭头误解为数据排序或趋势操作。

## 交互结构

字段设置弹窗采用双区域布局：

- 左侧“可选字段”按业务分类展示复选框，只负责选择和取消选择字段。
- 右侧“字段预览”只展示已选字段，并按最终表格列顺序编号。
- 上移、下移按钮只出现在字段预览中，不再出现在左侧分类列表中。
- 桌面端左右排列；窄屏和移动端改为上下排列，字段预览位于可选字段下方。

## 共享组件

- 商品运营与推广分析必须使用同一个原生 JavaScript 字段选择组件，不允许分别维护选择、预览和排序 DOM。
- 共享组件负责字段分组、复选框、预览列表、顺序调整、空态、计数和变更回调。
- 页面脚本只负责提供字段定义、初始顺序、模板数据以及应用或保存后的业务动作。
- 共享组件输出固定的“左侧可选字段、右侧字段预览”结构，避免页面样式或渲染顺序把预览列挤出布局。

## 状态规则

- 打开弹窗时，以当前模板或当前表格字段顺序初始化预览。
- 勾选新字段时，将字段追加到预览末尾。
- 取消勾选时，立即从预览中移除对应字段。
- 上移或下移只改变预览顺序，不改变字段的选中状态。
- 第一项禁用上移，最后一项禁用下移。
- 切换或套用模板时，同时刷新左侧勾选状态和右侧预览顺序。
- 保存自定义模板、应用字段和表格渲染均以右侧预览顺序为唯一数据源。
- 未选择字段时显示预览空态，并禁用保存模板和应用字段。

## 商品运营

- 保留现有字段分类、全选、清空、恢复经营模板和自定义模板能力。
- 删除分类列表中每个已选字段后面的上下箭头。
- 现有 `selectedDialogColumns()` 改为读取预览顺序，而不是依赖复选框 DOM 顺序。
- 使用模板、恢复模板、全选和清空后都重新渲染字段预览。

## 推广分析

- 所有支持字段设置的 TAB 使用相同预览组件和排序规则。
- 每个 TAB 的字段选择与顺序继续独立保存。
- 当前 TAB 的内置模板和自定义模板均保留模板中定义的字段顺序。
- “未提供归因”TAB 继续隐藏字段设置能力。

## 响应式与无障碍

- 弹窗宽度允许双列内容稳定展示，但不得超出视口。
- 移动端上下排列，预览列表和底部操作区不得产生横向滚动。
- 排序按钮使用可聚焦的原生 `button`，并提供包含字段名的 `aria-label` 和 `title`。
- 预览列表使用有序列表语义，序号同时表达当前列顺序。
- 状态变化继续通过现有 `aria-live` 区域反馈。

## 验收标准

- 左侧字段分类中不存在上移、下移按钮。
- 右侧预览仅包含当前已选字段，顺序与最终表格列顺序一致。
- 勾选、取消、全选、清空、模板切换和模板恢复都会实时同步预览。
- 排序后保存模板、关闭重开弹窗及刷新页面，字段顺序仍正确。
- 商品运营和推广分析各 TAB 均满足上述行为。
- 两个页面均加载并调用同一个字段选择组件。
- 390x844、768px、1024px 和 1440px 视口无横向溢出，底部操作按钮可见可用。
