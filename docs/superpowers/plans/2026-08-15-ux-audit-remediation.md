# 全站 UX / UI 整改方案

## 0. 审查结论

审查模式：Operate（经营分析后台）。本轮按 `impeccable critique`、`impeccable audit`、Web Interface Guidelines、运行时烟测和桌面/移动截图进行检查。

说明：当前会话没有可用的子代理接口，UX critique 按单上下文降级执行；机械检测器已独立运行，结果与人工观察分开核对。

当前判断：核心页面已经具备可用的统一 Token 基础，但整体仍处于“视觉规范已建立、产品体验未收敛”的阶段。粗糙感主要来自信息层级和组件重复实现，而不是单个颜色或圆角值。

## 1. 当前评分

| 维度 | 分数 | 判断 |
| --- | ---: | --- |
| 可访问性 | 3/4 | 核心弹窗、焦点恢复、表单标签和状态渲染已有基础；遗留页面的 Unicode 图标、重复控件实现仍有风险。 |
| 性能 | 3/4 | 页面烟测稳定；图表和缩略图加载策略仍可优化，部分图片使用 eager。 |
| 主题一致性 | 2/4 | 核心共享 CSS 已接入 Token，但遗留页面、内联样式、事件色板仍可绕过主题。 |
| 响应式 | 3/4 | 1366、1920、1024、390 均无页面溢出；商品宽表和设置长表单在移动端仍然疲劳。 |
| 实现完整性 | 2/4 | 同一产品存在多个独立 Shell、组件和图标语言，后续必然继续漂移。 |
| **总分** | **13/20** | **可用，但需要一轮结构性 UX 整改。** |

## 2. 已确认问题

### P1：首屏没有明确的决策顺序

位置：`overview.html`、`components.css` 的概览首页区域。

当前首屏连续堆叠 8 个 KPI、趋势、目标、待办、异常、矩阵、商品和报告。信息都重要，但没有明确告诉用户“现在先处理什么”。在桌面端表现为卡片密集，在移动端表现为长页面连续滚动。

整改方向：把首页重排为三层：

1. 结果层：4 个主 KPI，另外指标进入“更多指标”。
2. 决策层：趋势 + 目标进度 + 最高优先级异常/待办。
3. 证据层：日度矩阵、商品排名和报告，默认弱化或折叠。

验收：用户进入首页 5 秒内能找到当前结果、最大风险和下一步动作；首屏不再同时强调 8 个同权重指标。

### P1：商品页宽表可用，但缺少横向浏览引导

位置：`products.html`、商品数据表组件。

1440px 截图中表格右侧字段被截断在可视区域外，虽然页面没有 document overflow，但用户看不到还有更多列，也没有明显滚动阴影或冻结列提示。

整改方向：冻结选择框和商品列；表格容器增加横向滚动阴影/渐隐提示；默认只保留经营决策所需列，其他字段放入列设置；移动端切换为商品摘要卡片或分组字段视图。

验收：用户无需猜测就能发现横向内容；商品和选择列始终可见；390px 下不依赖极小字体阅读完整记录。

### P1：设置页移动端是“长表单墙”

位置：`settings.html`、设置相关组件。

移动端从基础设置一路连续展开到字段、模板、预警规则，输入项数量过大，保存动作不在持续可见范围内。页面虽然没有溢出，但中断后重新定位成本高。

整改方向：使用分段导航/手风琴，只展开一个设置域；顶部保留摘要和未保存状态；移动端底部提供 sticky 保存栏；危险或影响范围大的配置在保存前显示变更摘要。

验收：移动端单次只处理一个设置域；离开页面前能看到未保存状态；保存成功、失败和重试反馈位置固定。

### P1：同一产品存在多套视觉实现

位置：`refactor-a-demo.html`、`refactor-overview-v2.html` 与共享 Shell。

核心页面使用共享 Shell/Lucide/Token，但两个遗留演示页仍有独立布局、Unicode 图标、内联样式和重复按钮/面板实现。检测器已确认 A 方案存在 3 个 3px 彩色侧边条和扁平字号层级。

整改方向：先确认页面归属：

- 如果是废弃方案，从导航、发布入口和测试目标中移除，不再维护。
- 如果仍需保留，将其迁移到共享 Shell、共享组件和 Lucide，禁止独立视觉变量。

不接受第三种状态：页面继续可访问但没有明确的设计系统归属。

验收：所有可访问页面只有一个 Shell、一个图标库、一个组件状态语言。

### P1：状态色使用过重，削弱了语义

位置：概览异常、目标进度、生命周期/推广图表和提示块。

当前红、橙、绿、蓝同时出现在进度、异常、图表和列表中；异常块使用厚色侧边条和大面积浅色底，导致“风险”视觉重量接近普通信息。

整改方向：

- 品牌橙只用于主操作、当前选择和关键强调。
- 红色只用于真正需要处理的风险。
- 目标进度默认使用中性轨道 + 单一强调色，达成状态再使用成功色。
- 提示块改为 1px 边框或状态图标，不使用 3px 侧边条。
- 图表颜色固定为可解释的指标色板，并从主题 Token 读取。

验收：颜色本身不再承担唯一状态信息；截图中首要视觉焦点由业务优先级决定，而不是由颜色数量决定。

### P2：字体角色已定义，但实际层级仍偏密

位置：`tokens.css`、内联页面样式、图表配置。

当前存在 meta/secondary/body/label/section/title/KPI 多个角色，遗留页面还会直接使用 10/11/12px；小字、表格、状态和图表标签集中出现，导致阅读节奏扁平。

整改方向：保留语义角色，但减少页面实际使用的层级：

- 页面标题：20px
- 区块标题：16px
- 正文/控件：14px
- 辅助信息：12px
- KPI：24px

11px 仅允许用于极短的时间戳、表头或 badge；不用于连续说明文字。图表标签统一读取同一辅助信息 Token。

验收：每个页面最多出现 5 个可感知字号层级；长文本不使用 10/11px 连续排版。

### P2：核心交互状态还没有统一成“操作闭环”

位置：加载、空数据、失败、重试、保存和导入流程。

共享 `renderDataState` 已存在，但页面仍有局部状态渲染。用户需要在不同页面重新学习加载、错误和重试的位置与文案。

整改方向：统一状态组件协议：状态标题、原因、恢复动作、次要说明四个区域；保存/导入/刷新统一使用同一反馈位置；错误文案说明“发生了什么”和“下一步做什么”。

验收：每个 API-backed 页面都覆盖 loading、empty、partial、error、retry 五类状态，并有一致的视觉和键盘行为。

### P2：移动端可用，但不够适合单手和中断恢复

位置：全站 390px 视图，尤其设置、商品表格、数据中心工具箱。

当前烟测证明没有横向溢出，但不是所有工作流都适合移动端：关键操作集中在顶部，长列表和长表单缺少定位锚点，部分信息只靠滚动发现。

整改方向：移动端增加页面内锚点/分段导航、底部主要动作区、可折叠次要信息，并保留用户未完成输入和筛选状态。

验收：核心任务可以单手完成；从后台切回后不丢失当前筛选、表单草稿和展开状态。

### P3：遗留内联颜色仍会绕过主题

位置：`overview.html` 事件色板、`refactor-a-demo.html` 内联演示柱状图。

当前共享视觉门禁通过，但它只覆盖 `shell.css` 和 `components.css`，不能拦截页面内联样式。跨页面扫描仍发现 8 处直接颜色/字号值，主要集中在遗留页面和事件色板。

整改方向：将事件色板改为语义 Token 名称映射；将遗留页面内联演示样式抽成共享类；把页面、脚本和图表配置纳入同一门禁。

## 3. 实施顺序

### 阶段一：收口视觉来源

- 决定两个 `refactor-*` 页面是删除还是迁移。
- 扩展视觉门禁到所有 HTML 内联样式和非压缩 JS 动态样式。
- 完成所有动态图表、事件色板和状态提示的 Token 映射。
- 清除 Unicode 图标，统一 Lucide 和 aria-label/title。

### 阶段二：首页决策重排

- 重新定义首页信息优先级和首屏结构。
- KPI 从 8 个同权重卡片改为 4 主指标 + 可展开次要指标。
- 将异常、待办和目标进度组合为决策区。
- 日度矩阵和商品报告降级为证据区，保留现有数据和导出能力。

### 阶段三：商品与设置工作流

- 商品表冻结关键列、增加滚动提示、完善列设置和移动摘要视图。
- 设置页按域分段/折叠，增加 sticky 保存栏和未保存状态。
- 导入工具箱统一步骤状态、错误恢复和移动端操作区。

### 阶段四：状态、主题和可访问性

- 统一 loading/empty/error/partial/retry 组件协议。
- 亮色/暗色逐页验证正文、辅助文字、状态色、图表色和弹窗对比度。
- 用键盘跑通首页、筛选、表格、弹窗、设置和导入主流程。
- 检查 200% 文本放大、长文案、空数据和失败恢复。

### 阶段五：视觉收尾

- 统一截图评审：1440x900、1024x768、390x844。
- 只修复已确认的层级、间距、状态和响应式问题，不再添加新的视觉变体。
- 重新运行静态门禁、业务测试、核心页面烟测和暗色主题验证。

## 4. 不改的内容

- 不改 API 契约、数据库结构和业务计算。
- 不改变现有导航信息架构，除非阶段一确认遗留演示页为废弃入口。
- 不为了“看起来高级”增加渐变、玻璃拟态、装饰性动画或无业务意义的卡片。
- 不用更小字号解决表格拥挤，优先减少同时展示的信息量。

## 5. 验收门槛

- 共享 Shell、组件、页面内联样式和动态图表全部从同一 Token/组件协议取值。
- 生产可访问页面不再存在独立视觉语言或 Unicode 图标。
- 首页 5 秒可识别结果、风险和下一步动作。
- 商品页桌面和移动端均能发现并操作完整字段集。
- 设置页移动端能分段完成、保存、失败重试和恢复草稿。
- 12 个页面入口在桌面、平板、移动端通过浏览器烟测，无脚本错误和意外溢出。
- UX 审查评分达到至少 17/20，且 P1 问题清零。
