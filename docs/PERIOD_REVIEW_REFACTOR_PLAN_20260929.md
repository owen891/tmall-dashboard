### 1.2 差距

1. **驾驶舱无"三大指标完成率"结构**：XMind 总结第一层是 GSV 完成率/净利润完成率/
   费比三张卡，各带环比+同比；现有驾驶舱是"核心结果/目标差距/风险/待落地"四卡。
2. **段落是单 textarea**：XMind 每个板块总结都是"分析→根因→下一步规划"三段固定
   结构，根因是三层树；现有段落靠 placeholder 引导，无结构约束。
3. **tab 顺序不符合叙事**：XMind 顺序是品类汇总→货品→广告→市场→总结与规划；
   现有 tabs 把"动作与计划"放在第 2 位，拆因链条被切开。
4. **缺问题单品聚合视图**：七张榜单分散，用户需自行在脑中合并下滑+亏损+高费比。
5. **市场监控深度不足**：XMind 要求竞店 7 家 × 3 件事（整体/爆品排名变化/趋势品）、
   行业趋势市场/蓝海市场、关键词 8 大归类/词根/趋势节点；现有市场 tab 仅整体数据表。
6. **规划缺排期**：XMind 明确"任务时间节点排期"节点；next_plan 为纯文本。
7. **周月不互通**：XMind 销售指标下的"周维度"节点应由本月各周周复盘汇入月复盘。

## 3. P1 结构：段落三段式 + 保存结构 v3（预计 1–2 天）

### 3.1 模板升级（period_templates.py）

六段模板每段增加 `subsections` 定义（周月共用，仅提示文案随粒度变化）：

```python
{
    'key': 'goods',
    'title': '本月货品复盘（top单品 / 新品 / 问题单品 / 结构变化）',
    'subsections': [
        {'key': 'analysis', 'title': '分析', 'hint': '从榜单事实出发…', 'required': True},
        {'key': 'root_cause', 'title': '根因', 'hint': '从指标变化定位到具体原因…', 'required': True},
        {'key': 'next_step', 'title': '下一步规划', 'hint': '从根因导出可验收动作…', 'required': False},
    ],
    ...
}
```

- XMind 里**有根因树的板块**（品类汇总、货品、广告、市场）三段必填分析+根因；
  **无根因树的板块**（总结）保持单段或采用"做了什么/亮点/核心问题/卡点"子段。
- 周/月模板 `subsections` 结构相同——**同能**；粒度差异体现在素材密度与
  breakdown（月=分周、周=分日，后端 `_breakdown_block` period_context.py:215 已支持）。

### 3.2 保存结构 v3

```json
// sections: {key: {text: "...", subsections: {analysis: "…", root_cause: "…", next_step: "…"}}}
```

- 后端 PUT 校验（api/period_reviews_api.py:281-346）扩展 `subsections` 白名单校验：
  key 必须在该段 `subsections` 定义内，长度上限沿现有 text 校验。
- 兼容：`text` 字段永久保留。老复盘（纯 text）展示时 analysis 子段显示原 text
  （只读迁移，同 `migrate_sections` 思路）；新保存优先写 `subsections`，
  text 存三段拼接（保证旧版本前端/导出仍可读）。
- 导出（P3）优先用 `subsections`，缺省回退 text。

### 3.3 前端段落渲染（sectionNode，period-review-live.js:1715）

- 每段渲染 3 个子输入框（无 subsections 定义的段保持单框），标题带"分析/根因/下一步"角标。
- 草稿暂存（SECTION_DRAFT_KEY）key 扩展为 `sectionKey:subKey`，容量保护逻辑不变。
- 必填校验：required 的子段为空时标红，保存拦截逻辑同现有 `missingRequired`。

### 3.4 验收

- 老复盘（v1/v2 纯 text）打开不丢内容，analysis 子段回填原 text。
- 新保存后 GET 回来 subsections 完整；用旧结构请求 PUT 不被拒（text-only 兼容）。
- 既有测试 `tests/test_period_reviews*.py` 全绿 + 新增 subsections 校验用例。

## 6. 工作纪律与风险

- **每阶段独立提交**，提交信息沿用现有格式（`feat(period-review): …`）。
- **不模糊"事实与结论分离"**：根因必须人写，系统只给证据链。重构中不引入
  "系统自动生成根因"类功能；系统观察文案保持"不代替经营结论"的措辞纪律。
- **不重建专页功能**：市场深化只做摘要+深链；任务排期复用动作系统，不新建任务表。
- **迁移兼容是 P1 唯一高风险点**：v1→v2 已有 `migrate_sections` + `LEGACY_SECTION_ALIASES`
  先例，v3 沿用同思路（只读、幂等、text 永久保留），上线前用 8 月真实复盘数据回归。
- **每阶段验收依赖真实数据**：8 月同比 xlsx 与 XMind 中的数字（GSV 71.9 万、费比
  20.29% 等）可作对照基准。
- 测试基线：audit_core_interactions 有 3 项预存失败（见 memory），回归对比时排除。
